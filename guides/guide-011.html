먼저 현재 거래의 단계를 구분하세요

금액을 잘못 입력한 것을 발견하면 새 버튼을 누르기 전에 화면을 봅니다. 아직 승인 요청 전인지, 통신 처리 중인지, 이미 승인 결과가 나온 뒤인지에 따라 해야 할 일이 다릅니다. 처리 중 화면을 급하게 닫아도 기존 거래가 취소됐다고 판단할 수는 없습니다.

예를 들어 주문 합계가 36,000원인데 360,000원을 입력했다면 고객에게 오입력 사실을 설명하세요. 승인 전이면 안내된 정정 기능으로 금액을 다시 맞추고, 결과가 나왔다면 원거래를 확인해 취소 절차로 넘어갑니다. 어느 단계인지 모르겠다면 결과 조회가 먼저입니다.

승인 전에는 정정, 승인 후에는 거래 확인

입력값을 지우는 정정과 이미 승인된 금액을 취소하는 것은 다른 작업입니다. 버튼 이름이 비슷해도 기능을 추측하지 마세요. 실제 설치 안내에서 금액 정정과 거래 취소 경로를 각각 확인해 둬야 바쁜 시간에도 혼동이 줄어듭니다.

  1. 주문서의 정확한 금액과 단말기 입력값을 대조합니다.
  2. 승인 전이라면 안내된 정정 기능으로 수정하고 금액을 다시 읽습니다.
  3. 승인 후라면 해당 거래의 시각·금액·승인번호를 확인해 취소를 진행합니다.
  4. 취소 완료를 확인한 뒤 정확한 금액을 새로 결제하고 두 기록을 연결합니다.

차액만 처리하기 전 확인해야 할 것

잘못 받은 금액과 정상 금액의 차이를 계산했다고 해서 현금으로 돌려주면 모든 기록이 해결되는 것은 아닙니다. 부분 취소나 추가 결제가 필요한 상황은 매장 처리 기준과 지원 기능을 확인하세요. 임의의 처리는 주문 금액과 승인 내역이 서로 달라지는 원인이 될 수 있습니다(업계 표준상).

마감 때는 원래 잘못된 승인, 그 승인에 대한 취소, 새 정상 승인을 함께 봅니다. 직원 기록에는 ‘금액 수정 완료’만 쓰기보다 세 거래의 연결과 고객 안내 여부를 남기세요. 반복되는 오입력은 입력 속도를 탓하기보다 주문 합계 확인 위치, 추가 메뉴 반영 시점, 결제 전 금액 읽기 순서를 점검해 보시는 편이 좋습니다.

실행 점검표

  • 승인 요청 전·처리 중·승인 후를 구분했습니다.
  • 고객에게 잘못된 금액과 수정 순서를 안내했습니다.
  • 취소 완료 후 정상 금액을 다시 결제했습니다.
  • 오승인·취소·정상 승인 기록을 연결했습니다.

자주 묻는 질문

금액이 적게 결제됐으면 추가로 받으면 되나요?

원주문과 이미 받은 금액을 확인하고 고객에게 부족 금액을 설명하세요. 매장 기준에 맞는 추가 결제 또는 취소 후 재결제 방법을 정한 뒤 기록을 남깁니다.

직원이 취소 권한이 없으면 어떻게 하나요?

화면 상태와 거래 정보를 기록하고 책임자에게 넘기세요. 관리자 암호를 추측하거나 설정 메뉴를 바꾸지 말고 확인된 절차로 진행합니다.

참고 자료와 적용 범위

  • KIS정보통신 KIS-2420 공식 사용설명서 ↗승인·취소·재인쇄 구분 및 규격품 사용·외관 청소·임의 분해 금지의 일반 원칙만 참고. 다른 모델 설명서이므로 LC-7351QN 버튼·규격 근거로 사용하지 않았습니다.

자료 확인 기준: 2026-09-19. 개별 계약·업종·신고 상황에 따라 적용 내용을 확인해 주세요.
