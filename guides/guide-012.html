알림 개수와 거래 개수를 구분합니다

고객이 두 번 결제됐다고 말하면 먼저 불편을 인정하고 정확한 내역을 확인하겠다고 안내합니다. 단말기 전표 두 장, 문자 두 개, 실제 승인 두 건은 같은 뜻이 아닙니다. 승인과 취소 알림이 각각 도착했을 수도 있고 같은 거래를 재출력했을 수도 있습니다.

주문서 기준으로 받아야 할 금액이 얼마였는지 확인하고, 해당 시간대의 거래 내역을 찾습니다. 거래 시각·금액·승인번호·취소 상태를 나란히 적으면 서로 다른 승인인지 구분하기 쉽습니다. 고객의 휴대전화를 가져와 다른 결제 내역까지 살피기보다 필요한 거래만 보여 달라고 요청하세요.

중복 여부를 확인하는 순서

같은 금액의 승인번호가 두 개라는 사실도 주문 기록과 함께 봐야 합니다. 두 테이블이 같은 금액으로 따로 결제한 상황일 수 있기 때문입니다. 반대로 한 주문에 대해 재시도한 흔적이 있고 두 승인이 모두 유효하다면 어느 거래를 유지할지 책임자가 확인해 처리합니다.

  1. 주문 한 건의 정상 결제 예정 금액과 당시 직원 기록을 확인합니다.
  2. 해당 시간대 승인·취소 내역을 조회해 거래별 상태를 대조합니다.
  3. 실제 중복으로 확인된 거래만 정해진 취소 절차로 처리합니다.
  4. 유지할 승인 한 건과 취소 완료 기록을 확인하고 고객에게 설명합니다.

조회 결과가 서로 다를 때

매장에서는 한 건만 보이는데 고객은 두 건이 보인다면 바로 별도 환불부터 하지 마세요. 확인한 승인 정보를 관리 담당자와 카드 발급처에 전달할 수 있도록 정리합니다. 결과가 불명확한 상태에서 추가 송금을 하면 이후 취소 반영과 겹쳐 정리가 복잡해질 수 있습니다(업계 표준상).

예시로 통신 지연 때문에 직원이 재결제를 한 경우에는 첫 시도와 두 번째 시도의 시간 간격을 기록하세요. 해결 뒤에는 ‘응답이 늦을 때는 재승인보다 조회 먼저’라는 기준을 공유합니다. 처리 완료는 손님을 보낸 시점이 아니라, 유지할 거래와 취소할 거래의 최종 상태를 확인한 시점으로 기록하는 편이 좋습니다.

실행 점검표

  • 문자·전표 장수와 실제 승인 건수를 구분했습니다.
  • 주문 한 건과 거래 내역을 연결했습니다.
  • 중복으로 확인된 거래만 취소했습니다.
  • 고객 안내와 최종 거래 상태를 기록했습니다.

자주 묻는 질문

영수증 승인번호가 같으면 어떻게 보나요?

같은 거래의 재출력인지 날짜·금액·상태까지 함께 확인하세요. 승인번호만 단독으로 보지 말고 공식 거래 조회 결과와 대조하는 것이 좋습니다.

고객이 급하다고 하면 바로 현금으로 돌려줘도 되나요?

확인되지 않은 중복에 대해 임의 지급부터 하지 마세요. 확인 담당자와 연락 방법을 안내하고 원거래 상태를 먼저 확인하는 운영 기준을 권합니다.
